GridPulse - how to run
======================

Needs: Java 17+, Node 20, and either Docker Desktop or a local MySQL 8 (+ Kafka in Docker for emails / refunds).


What runs where
---------------
   port   service                 what it does
   8080   gateway                 the one address the site calls: routes, CORS, rate limits (429)
   8081   angular (npm start)     the site
   8082   core-service            accounts, tracks, sessions, bookings, waitlist, race control, feedback
                                  (a second core instance: 8083)
   8084   notification-service    every email (codes, invites, booking decisions + e-ticket, refunds, waitlist,
                                  urgent feedback for the admins)
   8085   payment-service         razorpay orders, the confirm saga with the core, refunds
   8086   ai-service              the faq chat (logged out), the Copilot (logged in: reads + Confirm cards),
                                  feedback labels / suggestions / summary (groq)
   3306 mysql · 6379 redis · 9092 kafka · 8090 kafka ui

   How they talk: the browser only talks to the gateway. Services call each other's /internal/** with
   INTERNAL_API_KEY (the gateway never routes /internal/**) and pass the user's own token along.
   Changes travel as events (outbox -> Kafka): emails, refunds, payment badges, feedback labels, live boards.
   No Kafka = the site works, but emails, refunds and labels wait until Kafka is back.


First run (once)
----------------
1. Secrets: cp secrets.properties.example secrets.properties and fill in what you have
   (empty = that feature is off). One file for every service; an environment variable with the same name wins.
   Set the same JWT_SECRET and INTERNAL_API_KEY for all services (they are in that one file).
2. Infra: cp .env.example .env, then  docker compose up -d mysql redis kafka   (kafka-ui optional)
   or a local MySQL 8 on 3306 (user root, its password goes into secrets.properties as DB_PASSWORD) and only  docker compose up -d kafka.
   DB_PASSWORD in secrets.properties = MYSQL_ROOT_PASSWORD in .env (required, no default).
   The databases appdb, payment_db, ai_db and notification_db are made on the first start.
3. Shared code: ./mvnw -q install -DskipTests -pl common   (again after every change in common/)
4. Only for an appdb from before phase 5 / 6 (once, in this order):
   start the core once, then             mysql -uroot -p < docker/sql/phase5-backfill-core.sql
   start payment-service once, then      mysql -uroot -p < docker/sql/phase5-copy-payments.sql
   BEFORE the first start of ai-service: mysql -uroot -p < docker/sql/phase6-copy-chat.sql
   (old payments keep their refunds; the faqs keep their gemini vectors, which saves the daily quota)


Mode A - terminal (light: infra in Docker / local MySQL, services from the repo root)
-------------------------------------------------------------------------------------
   start order: core -> notification -> payment -> ai -> gateway (one terminal each)
   CORS_ENABLED=false ./mvnw -pl core-service spring-boot:run   http://localhost:8082
   ./mvnw -pl notification-service spring-boot:run           http://localhost:8084
   ./mvnw -pl payment-service spring-boot:run                http://localhost:8085
   ./mvnw -pl ai-service spring-boot:run                     http://localhost:8086
   ./mvnw -pl gateway spring-boot:run                        http://localhost:8080 (what angular calls)

   no Redis:            CACHE_TYPE=none for the core and ai-service (no cache, same answers)
   emails to files:     MAIL_TO_FILE=true ./mvnw -pl notification-service spring-boot:run (target/test-mails)
   two core instances:  SERVER_PORT=8083 CORS_ENABLED=false ./mvnw -pl core-service spring-boot:run
                        SPRING_PROFILES_ACTIVE=docker CORE_2_URL=http://localhost:8083 ./mvnw -pl gateway spring-boot:run
                        (which one answered: the X-Served-By header, dev only)

   health:   http://localhost:<port>/actuator/health for every service
   swagger:  http://localhost:8082/swagger-ui.html (the core, not in prod): log in, copy "token", Authorize
   the gmail check of notification-service: its log line "EMAIL: ..." (notification-service/logs)


Mode B - full Docker (everything in containers; heavy: 6 services + the infra)
-----------------------------------------------------------------------------
   fill the keys in .env (JWT_SECRET and INTERNAL_API_KEY are required; MAIL_*, SUPER_ADMIN_*, RAZORPAY_*,
   GEMINI_*, GROQ_API_KEY ... see .env.example)
   ./mvnw -q package -DskipTests      build the jars first: the images only copy <module>/target/*.jar
   docker compose --profile apps up -d --build
       gateway :8080, core-1 :8082, core-2 :8083, notification :8084, payment :8085, ai :8086 + the infra
       (core-2 starts once core-1 is healthy; each service gets a 256 MB heap, APP_JAVA_OPTS in .env changes it)
   docker compose --profile ui up -d  kafka ui on http://localhost:8090 (it only starts with --profile ui)
   docker compose stop core-2         the site keeps working on core-1
   docker compose --profile apps down


Frontend (http://localhost:8081)
--------------------------------
   cd frontend && npm install && npm start
   logged out the chat bubble answers from the FAQ list; logged in it is the Copilot ("Copilot · <role>"):
   it reads your data and shows every change as a card that only happens when you press Confirm.


Settings (environment variables, all optional; keys live in secrets.properties)
-------------------------------------------------------------------------------
   JWT_SECRET                      64+ characters, the same everywhere; empty = a key file in ~/.gridpulse
                                   (one machine only: the other services read the core's file, start it first)
   INTERNAL_API_KEY                32+ characters, the same everywhere; empty = a fixed dev key + warning
   DB_HOST / DB_PORT               mysql, default localhost / 3306 (core: ignored when DB_URL is set)
   PAYMENT_DB_URL / AI_DB_URL / NOTIFICATION_DB_URL   the other services' databases
   SERVER_PORT                     core port, default 8082
   PAYMENT_PORT / AI_PORT / NOTIFICATION_PORT         8085 / 8086 / 8084
   CORE_1_URL / CORE_2_URL         where the core instances run (gateway, payment-service, ai-service)
   PAYMENT_URL / AI_URL            where payment-service / ai-service run (gateway + core + ai-service)
   CORS_ENABLED                    false = the core answers no CORS (behind the gateway); default true
   KAFKA_BOOTSTRAP                 default localhost:9092
   REDIS_HOST / REDIS_PORT         default localhost / 6379;  CACHE_TYPE=none = no redis needed
   FRONTEND_URL                    where the site runs (invite links), default http://localhost:8081
   TICKET_SECRET                   signs the e-ticket QR codes; empty = dev secret + warning
   MAIL_TO_FILE                    true = emails go to notification-service/target/test-mails
   RAZORPAY_BASE_URL               payment-service: razorpay api, default https://api.razorpay.com/v1
   GRIDPULSE_JOBS_REFUND_ENABLED   payment-service: false = no refund job here (run it on one instance only)
   GEMINI_GENERATION_MODEL         ai-service: default gemini-flash-latest (google retired gemini-2.5-flash)
   GEMINI_TIMEOUT_SECONDS          ai-service: per gemini call, default 25


Tests
-----
   unit tests, no Docker:   ./mvnw -q -pl common,notification-service test
   integration tests (need Docker: their own MySQL, some also a Kafka; no real AI or payment is ever called):
                            ./mvnw -pl core-service verify
                            ./mvnw -pl payment-service verify    (wiremock plays the core, razorpay is faked)
                            ./mvnw -pl ai-service verify         (wiremock plays the core + payment, no model)
   core: concurrency (car numbers, last seat), internal api rules, payment events once, waitlist, feedback labels
   + urgent event, security, admin pages, e-ticket, stats, circuit breakers, outbox -> kafka.
   payment-service: booked -> PAID, refused -> refund, core too slow -> 202 -> the job finishes, refund once.
   ai-service: tools per role, prepare changes nothing, Confirm only by its owner / once / in time, with the
   caller's token; FeedbackSubmitted -> FeedbackLabelled over kafka, once.
   one class only:  ./mvnw -pl core-service test -Dtest=StatsIntegrationTest
   skip them:       ./mvnw package -DskipTests
